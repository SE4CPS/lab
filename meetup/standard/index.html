Reused Standard: OpenAPI

2011 → today
OpenAPI Spec
Governed by the OpenAPI Initiative (Linux Foundation), not one vendor.
Source: openapis.org
  • One file = every call an agent can make
"paths": {
  "/users/{id}": {
    "get": {
      "operationId": "getUser",
      "parameters": [{
        "name": "id",
        "in": "path",
        "required": true
      }]
    }
  }
}

Reused Standard: JSON Schema

2009 → today
JSON Schema
Independent, vendor-neutral vocabulary for JSON shapes.
Source: json-schema.org
  • Describes a tool's inputs, validates its output -- same schema
// get_weather tool
{
  "type": "object",
  "properties": {
    "city": { "type": "string" },
    "units": {
      "enum": ["C", "F"]
    }
  },
  "required": ["city"]
}

New Standard: W3C Verifiable Credentials & DIDs

DID: 2022 · VC 2.0: 2025
Verifiable Credentials / DIDs
A signed, checkable identity -- no single issuer required.
Source: w3.org/TR/vc-data-model-2.0, w3.org/TR/did-core 
{
  "type": ["VerifiableCredential"],
  "issuer": "did:web:example.org",
  "credentialSubject": {
    "id": "did:key:agent123",
    "role": "agent"
  }
}

Adoption Playbook

  • Prefer a standard over a bespoke shape
  • Map your pipeline to 42001's PDCA loop
  • Run an IEEE 7000 review before shipping
  • Scope every OAuth token tightly
// bespoke
{ "usr_nm": "Ana",
  "is_ok": 1 }

// standard (JSON Schema)
{ "name": "string",
  "active": "boolean" }

Standards, Not Silos

The most durable parts of the agent stack won't be any one vendor's protocol -- they'll be the ISO, IEEE, and open specs that outlive it.
