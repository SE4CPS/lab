What Is a Prompt?

A prompt structured input for LLMs

  • System - who the model is, its rules and constraints
  • Context - the situation: platform, screen, state
  • Task - what to do: write, test, fix, explain
  • Format - how to respond: framework, style, length

A well-structured prompt is deterministic input - same structure, same quality output.

Unlike a chat message, a prompt is versioned, reusable, and parameterised with context

Example

# SYSTEM
You are a senior mobile QA engineer.
Assert behaviour only - no speculation.

# CONTEXT
App: Shop Screen: LoginForm
Platform: iOS Safari  Viewport: 390px

# TASK
Write component tests for the login form.
Cover: empty submit, invalid email, success.

# FORMAT
Vitest + RTL · one describe block
fireEvent.touchEnd not click
Fail loudly with clear messages.
Key insight: the prompt is the spec - write it before asking the agent to generate anything

What Is an Agent?

An agent is a loop

  • Think - LLM reads context, goal, memory
  • Plan - LLM selects and sequences steps
  • Act - tools execute: write, run, read, search
  • Observe - tool output fed back into LLM context
  • Learn - LLM synthesises result, updates memory

Not a single call - a running loop that stops when the goal is met or it gives up.

LLM reasons at Think · Plan · Learn  ·  Tools execute at Act · Observe

In testing: Think: read agents.md · Plan: list test cases · Act: write + run · Observe: failure · Learn: update §12

More Generated Code - More Testing Matters

Why confidence shrinks as output grows

  • Each LLM call adds code you did not write
  • Agent loops stack changes across many files
  • Unverified output compounds - bugs hide deeper
  • No tests = no signal when generation drifts
  • Tests are the only objective measure of agent output

The faster code is generated, the faster bad code is generated - tests are the speed limit

Rule: agent generates 500 lines across 3 files - without tests you have no idea if any of it works

Controlling Token Growth - Reuse Over Regeneration

Problem - agent repeats boilerplate

// agent writes this in every test file:
const wrapper = ({ children }) => (
  <Provider store={createStore()}>
    {children}
  </Provider>
);
const mockUser = { id:1, email:'a@b.com' };
// × 20 files = ~800 repeated tokens

Fix - add §rules to agents.md

## §rules - test libraries
- render: import from ../../test-utils
- users: import from test/factories/user
- Never write inline mock data
- Never redefine render wrappers
Rule: agents.md §rules: "import renderLogin from ../../test-utils - never redefine render wrappers"

Best Practices

Do

  • State platform + viewport in every prompt
  • List states: empty, loading, error, success
  • Paste stack traces back into the loop
  • Append resolved fails to agents.md §12

Do not

  • "Test everything" - agent over-generates
  • Use click on mobile touch targets
  • Accept green tests without reading them
# Good prompt
CONTEXT: LoginForm · 375px · iOS
TASK: test empty submit
ASSERT: error "Email required" shown
FORMAT: Vitest + RTL · one describe
# Bad prompt
"Write tests for the login form"
Running example: bad: "test login" - good: "TASK: test empty submit shows error"
