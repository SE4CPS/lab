Evidence-Gated Question Answering
User Query (version / patch / CVE)
⬇️
Meaning Identification (intent + vendor scope)
⬇️
Evidence Retrieval (release feeds, vendor repos, advisories)
⬇️
Evidence Evaluation (relevance, consistency, freshness)
⬇️
Answerability Decision
Structured Response
evidence sufficient
Abstain: “I don’t know”
evidence weak, stale, or missing
Why the System Abstains
  • No vendor match → abstain (confidence 0.30)
  • Vendor found, no supporting evidence → abstain (confidence 0.80)
  • Abstention responses stay context-aware, e.g. “I don’t know about <vendor> for <intent>”
  • Abstention is a correct outcome, not a failure

Answer When Evidence Exists, Abstain When It Doesn’t

Version Query (NVIDIA)

User asks for the most recent driver version. Vendor is validated, release artifacts filtered by relevance and freshness.

Evidence-backed answer returned

CVE Query (Windows)

User asks whether a fix exists for a specific CVE. Advisories checked for consistency and recency.

Answers if confirmed, otherwise abstains

Single-Agent vs. Multi-Agent, Same Question

"Are there known Siri issues following the iOS 26.4/26.4.1 updates?"

Single-Agent RAG

"Try updating Siri settings. The issue may have been fixed in a recent update."

Limited supporting evidence

Multi-Agent RAG

"iOS 26.4 introduced changes affecting Siri offline task execution. Multiple users report the same behavior following the update."

Grounded in retrieved sources
