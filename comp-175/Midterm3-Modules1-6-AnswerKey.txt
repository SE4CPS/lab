Question 19 (Backup Planning)

Full credit needs:
- A real scp (or rsync-over-ssh) command copying each patient's own
  ID-named home directory to a backup destination, e.g.
  scp -r admin@medical-vm:/home/<patient-id> /backup/<patient-id>/
- Recognizes this needs to run per patient directory, not just once
  (a loop, a wildcard, or an explicit list of patient IDs)
- Automation via crontab: a real cron line (e.g. a nightly schedule
  like 0 2 * * *) running the backup command, with output logged
  somewhere checkable rather than silently discarded

Partial credit: gets the scp command right but doesn't address
automation, or proposes crontab without a real command/schedule.

No credit: proposes manually copying files with no scripted/
scheduled mechanism, or confuses scp with an unrelated tool.

Question 20 (Intern Onboarding, 3 Safeguards)

Full credit needs three genuinely distinct safeguards, for example:
- A separate, individual account for the intern (not a shared
  root/admin login), with sudo scoped to only what their tasks
  need (least privilege, Module 4)
- Working against a snapshot or a cloned test VM instead of the
  real production medical VM directly, so any mistake can be
  rolled back without touching real data
- Permissions/ACLs on the sensitive medical-data directories that
  give the intern's account no write or delete access there at all

Partial credit: names 1-2 real safeguards, or repeats the same idea
phrased two different ways instead of three distinct ones.

No credit: gives the intern the existing admin's own login/password,
or proposes no actual technical safeguard (e.g. "just tell them to
be careful").
