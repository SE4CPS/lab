PART 2: DIAGRAM QUESTION (19) -- GRADING GUIDE
================================================================

Full credit needs:
- The Ubuntu host and the Docker container running the web app shown as
  distinct, labeled boxes
- The firewall (iptables/nftables) shown between the internet and the host
- fail2ban shown watching the SSH login log, with a labeled connection to
  the firewall showing it can add a block rule
- The exposed port mapping (e.g. 8080 -> 80) labeled on the connection
  between the container and the host

Partial credit for a correctly drawn container + firewall setup that is
missing the fail2ban-to-firewall link. No credit if fail2ban or the
firewall is omitted entirely, or if the container and host are drawn as
the same box.

================================================================
PART 3: WRITTEN RECOMMENDATION (20) -- GRADING GUIDE
================================================================

Full credit expects:
- A systemd timer or cron job scheduling the backup to run automatically
  every night
- A failure-handling approach in the script itself (e.g. set -euo
  pipefail and a trap on ERR) that logs clearly and alerts immediately if
  the backup breaks partway through
- A scoped, limited-privilege approach (e.g. sudo -l / a narrow sudoers
  entry via visudo) that lets the two student workers check on the
  backup without ever needing the shared root password

Partial credit for a workable automation/logging scheme that omits the
access-control follow-up. No credit for a scheme that simply shares the
root password with both student workers "for convenience."
